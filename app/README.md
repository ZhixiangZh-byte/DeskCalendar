# DeskCalendar 桌面组件

一组贴在 Windows 桌面上的透明组件，直接读写 Google Calendar 和 Google Tasks。按 Win+D 显示桌面时它们仍然可见；平时其他窗口会盖住它们。

| 组件 | 内容 |
|---|---|
| 月历 | 事件和任务按日期排在月历网格中 |
| 日视图 | 顶部是全天日程和当天的任务，下面是 0–24 点的时间轴（定时事件按时间排列，重叠的并排显示，红线表示当前时间）；‹ › 切换日期 |
| 四象限 | 所有未完成的任务（有无日期都算，不含长期规划），按重要 × 紧急分成四格；逾期日期显示为红色 |
| 回顾箱 | 逾期未完成的任务 + 最近 30 天完成的任务 |
| 长期规划 | Google Tasks 中"长期规划"清单里的任务（第一次新建时自动创建这个清单） |

## 使用

1. 前提：`%USERPROFILE%\.deskcalendar\google-oauth-client.json` 已存在（"桌面应用"类型的 OAuth 客户端）。
2. 在资源管理器中双击 `src-tauri\target\release\DeskCalendar.exe`。不要从 Claude 里启动，否则缓存和设置会被重定向到 Claude 的私有目录。
3. 点"登录 Google"，在浏览器中授权。出现"Google 未验证此应用"时点"继续"。所有组件共用这一次登录。
4. 默认只显示月历。其他组件在**托盘图标右键菜单 → 显示组件**中打开；组件顶栏最右的 × 可关闭该组件。

| 操作 | 方法 |
|---|---|
| 新建任务 | 点空白处：月历 / 日视图的全天区建当天的任务；四象限的某一格建不设日期、带对应标记的任务；长期规划建到"长期规划"清单。回车或 Ctrl+Enter 添加 |
| 快速标记 | 标题末尾加 `!` = 重要，`!!` = 紧急，`!!!` = 重要且紧急（半角、全角都可以）；也可以勾选"重要"/"紧急" |
| 新建日历事件 | 新建时勾选"指定时间"，会建成主日历中的事件。日视图里点时间轴空白处，会按点击位置预填开始时间（取整到半小时） |
| 查看 / 编辑任务 | 点任务标题，打开详情：可改标题、详情、日期（可清空）、重要/紧急、完成状态；可删除（需再点一次确认） |
| 完成 / 取消完成 | 点任务前的方框 |
| 查看 / 编辑日程 | 点日程打开详情。自己日历上的日程（自己组织或允许嘉宾修改的）可改标题、全天/定时、起止日期时间、地点、说明，也可删除；重复日程只改这一次。别人组织的会议和只读日历只能查看。没改说明时不会写回，保留 Google 中的富文本格式 |
| 关闭面板 | 点面板外的任意位置，或按 Esc |
| 鼠标穿透 5 秒 | 顶栏的指针图标，只作用于当前组件；期间卡片变淡，可点到组件后面的桌面图标 |
| 翻页 | 月历、日视图顶栏的 ‹ › ；"今天"回到当前 |
| 移动 / 调整大小 | 拖动顶栏 / 拖动边缘；每个组件分别记住自己的位置和大小 |
| 设置 | 顶栏齿轮：外观（跟随系统 / 浅色 / 深色）、背景不透明度、显示已完成的任务、显示农历和传统节日、锁定位置和大小、退出登录。设置对所有组件生效 |
| 农历 | 月历每格在公历日期旁显示农历（初一显示月名，传统节日以红字显示）；日视图顶部显示"农历 丙午马年 九月十五 · 节日"。可在设置中关闭 |
| 托盘菜单（右键） | 显示组件、立即刷新、锁定、鼠标穿透（所有组件）、开机自动启动、退出登录、退出 |

显示与刷新：
- 显示 Google 日历里所有处于勾选状态的日历；任务来自除"长期规划"外的所有清单（长期规划组件除外）。
- 任务前的红点表示 `#重要`，橙点表示 `#紧急`（来自备注末尾的标签行）。
- 在任一组件里修改数据后，其他组件会立即刷新；另外每 3 分钟自动刷新，窗口获得焦点、网络恢复时也会刷新。离线时显示上次缓存的数据。
- **增量刷新**：第一次全量读取后，每次刷新只取上次以来修改或删除的条目并合并（日历列表和任务清单沿用上次的结果）；每 15 分钟，以及翻月 / 翻天时，重新全量读取一次。
- **离线修改**：断网时新建、修改、勾选、删除都照常进行。修改保存在本地队列（所有组件共用），条目显示为橙色虚线框，顶栏状态点旁显示待同步数量。网络恢复、启动或下一次刷新成功时，按顺序自动提交。本地新建的条目同步后换成 Google 的真实 ID，之后的修改照常生效。如果某项修改被 Google 拒绝（例如条目已在其他设备上删除），会放弃这一项并在状态栏提示。退出登录会清空未同步的修改。
- **离线时打开新组件**：联网时，后台每 30 分钟最多一次，为所有组件（包括还没打开的）取数据并缓存，所以离线时第一次打开某个组件也有内容。如果某个组件仍然没有自己的缓存（例如离线时翻到从没看过的月份），会从其他组件的缓存中挑出属于它的条目显示，状态提示为"根据其他组件的缓存显示（可能不完整）"。

## 文件与数据

| 内容 | 位置 |
|---|---|
| OAuth 客户端 | `%USERPROFILE%\.deskcalendar\google-oauth-client.json`（不在仓库中） |
| 刷新令牌 | Windows 凭据管理器 → 普通凭据 → `DeskCalendar` |
| 锁定状态、显示哪些组件 | `%APPDATA%\com.deskcalendar.app\settings.json` |
| 各组件的位置和大小 | 由 window-state 插件保存在同一目录 |
| 数据缓存、外观偏好、离线修改队列 | WebView2 的 localStorage（`%LOCALAPPDATA%\com.deskcalendar.app`），所有组件共用 |

注意：Google 同意屏幕处于"测试"状态时，登录 7 天后失效，组件会提示重新登录。改为"正式发布"即可避免。

## 开发

```bash
npm install
npm run check                                 # 类型检查 + 单元测试（Vitest）
npm run dev                                   # 只启动界面，浏览器中用演示数据预览（?view=day 等切换视图）
npm run tauri build -- --debug --no-bundle    # 调试版 exe（带控制台窗口）
npm run tauri build -- --no-bundle            # 发布版 exe
```

- 启动参数：`--demo` 使用演示数据，不登录 Google；`--widgets=month,day,...` 本次运行显示指定组件（不改动保存的选择）。
- 模拟断网（仅演示数据）：在开发者工具控制台执行 `globalThis.__DESKCAL_DEMO_OFFLINE__ = true`；恢复时设为 `false` 并执行 `dispatchEvent(new Event('online'))`。
- `scripts/smoke.ps1 [-Release]`：以演示数据启动全部五个组件，检查窗口所有者是否为桌面窗口、按 Win+D 后是否位于桌面之上。运行时会短暂"显示桌面"。
- Rust 单元测试：`cd src-tauri && cargo test`。
- 更换图标：`npx tauri icon ..\calender_2.png`（源图为 1254×1254 的透明 PNG，位于仓库根目录），然后删除生成的 `icons/android`、`icons/ios`。**换图标后要先修改一下 `src-tauri/build.rs` 的时间戳**（或 `cargo clean`），否则构建脚本不会重新嵌入 exe 图标。

代码结构：

| 文件 | 内容 |
|---|---|
| `src-tauri/src/oauth.rs` | OAuth（回环地址 + PKCE）、凭据管理器、访问令牌刷新 |
| `src-tauri/src/desktop.rs` | 贴桌面层：把窗口的所有者设为桌面窗口（见 `../feasibility/README.md`） |
| `src-tauri/src/lib.rs` | 组件窗口的创建与关闭、托盘菜单、锁定、鼠标穿透、开机自启、提供给前端的命令 |
| `src/google.ts` | Google REST 客户端（收到 401 时刷新令牌并重试） |
| `src/model.ts` | 统一的条目模型：事件和任务的转换、四象限标签 |
| `src/source.ts` | 数据源（Google / 演示）、各组件的查询、增量刷新与合并、本地缓存 |
| `src/outbox.ts` | 离线修改队列：排队、预览叠加、按顺序提交、临时 ID 换真实 ID |
| `src/month.ts` | 月历网格 |
| `src/lunar.ts` | 农历换算（Intl 中国历，无需自带历表）、传统月名日名、干支生肖、传统节日 |
| `src/views.ts` | 五个视图：查询、标题、渲染；时间轴布局、四象限和回顾箱分组 |
| `src/ui.ts` | 共用的界面片段：条目行、新建 / 任务 / 事件 / 设置面板 |
| `src/prefs.ts` | 外观偏好（跨组件同步） |
| `src/main.ts` | 控制器：加载、刷新、面板与交互、跨组件通知 |
