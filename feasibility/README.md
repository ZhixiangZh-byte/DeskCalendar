# 可行性验证结果（2026-10-24）

结论：**方案可行**。Google API 满足需求；透明桌面组件可以贴在桌面上，按 Win+D 后仍然可见并且能正常交互。

## 1. Google Calendar / Tasks API（`google/`）

运行方式：用户在自己打开的终端中执行 `node feasibility\google\verify-google.ts`，然后在浏览器中授权。结果写入 `google/report.json`（不含令牌，已被 git 忽略）。

**16/16 通过**：

| 编号 | 内容 |
|---|---|
| G1、G0 | 桌面应用 OAuth（本机回环地址 + PKCE）授权成功，三项权限全部授予；刷新令牌可以换取新的访问令牌 |
| G2、G3 | 读取日历列表（主日历时区 Asia/Singapore）；读取本月事件（重复事件按单次展开） |
| G4、G5 | 新建带具体时间的事件（`+08:00`）和私有扩展属性；修改事件后返回新的 etag，可用于检测冲突 |
| G6、G7 | 用 syncToken 增量同步：新建的事件和删除（`cancelled`）都能获取到 |
| T1 | 读取任务清单和任务。任务的字段只有 `title/notes/due/status/completed/hidden/position/updated/links/webViewLink` 等，**没有优先级、重复规则或自定义字段** |
| T2、T3 | 新建带日期的任务，备注末尾的 `#重要 #紧急` 原样保存；**截止时间的时间部分被丢弃**（写入 15:30，读回为 `T00:00:00.000Z`），与文档一致 |
| T4–T8 | 完成（自动记录完成时间）、用 updatedMin 增量获取、取消完成、新建无日期任务、删除清单 |

对设计的影响：所有已定决策都能实现。有具体时间的计划建成日历事件；可勾选的计划建成任务，只到日期；四象限用备注末尾的标签。

## 2. 桌面层原型（`desktop-layer/`）

Tauri 2 无边框透明窗口，用 `--mode=` 切换四种模式。自动检查脚本：
- `selftest.ps1`：分别用 Shell.ToggleDesktop 和模拟 Win+D 显示桌面，检测组件是否仍然可见；
- `interact.ps1`：在显示桌面的状态下模拟点击、打字、拖动，读取原型报告的事件。

两个脚本都要求 DPI 感知（本机显示缩放为 200%）。

| 模式 | 做法 | Win+D 后 | 交互 |
|---|---|---|---|
| **owned（采用）** | 普通顶层窗口，所有者设为桌面窗口（Progman），失去焦点后退到底层 | ✔ 可见 | ✔ 点击、键盘、输入法、拖动、调整大小、透明度、鼠标穿透都正常（自动测试 + 用户手测） |
| desktop | 作为子窗口挂到 Progman 下（壁纸类软件的做法） | ✔ 可见 | ✘ 完全收不到鼠标和键盘输入 |
| bottom | 普通窗口，始终置于底层（对照组） | ✘ 被桌面图标盖住 | — |
| normal | 带任务栏按钮的普通窗口（对照组） | ✘ 被最小化 | — |

已知现象（用户认为可以接受）：其他窗口在前面时点击组件，组件会闪一下，随即退回底层。原因是窗口先被激活提到前面，失去焦点时又被压回底层。如果以后想消除这个闪烁，可以在 `WM_WINDOWPOSCHANGING` 中拦截"提到前面"的操作。

本机环境：Windows 11 Home 10.0.26200，桌面图标层（`SHELLDLL_DefView`）位于 Progman 下（24H2 之后的新结构）。旧结构（图标层在顶层 WorkerW 下）的兼容代码已写入 `desktop_host()`，但没有实测过。

注意：从 Claude 桌面应用内启动原型时，WebView2 的数据目录会被重定向到 Claude 的私有目录；用户手测时要从资源管理器启动。
